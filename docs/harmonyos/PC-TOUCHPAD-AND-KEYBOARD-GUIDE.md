# PC 触控板与键盘交互指南

## 当前交互

星图区域同时支持 ArkUI 的鼠标事件和轴事件。触控板的双指滑动、双指捏合由 `onAxisEvent` 接收；鼠标滚轮也走同一条轴事件路径。单指点击、单指拖动和鼠标左键仍由星图选择/旋转路径处理。

- 单指点击或鼠标左键：选中天体。
- 单指拖动或按住鼠标左键拖动：旋转星图，松手后保留惯性。
- 触控板双指滑动：平移星图。
- 触控板双指捏合：以指针位置为锚点缩放星图。
- 鼠标滚轮：缩放星图；触控板双指捏合以指针位置为锚点缩放。
- 键盘方向键：平移星图；`+` / `-`：缩放；空格：将已选天体居中；回车：执行居中；`F`：打开搜索；`N`：切换夜间模式；`Esc`：关闭当前面板。

## 本次修复

触控板捏合上报的是连续比例，而原生 `zoomBy` 需要先收到一次 `started=1` 的起始事件，再收到连续比例，最后收到 `endPinch`。此前 ArkTS 只发送了连续比例，Qt 侧没有建立捏合状态，所以部分 PC/2in1 设备上缩放完全没有效果。现在会按 `AxisAction.BEGIN/UPDATE/END` 建立、更新和结束捏合，并把当前指针坐标与星图尺寸传给原生锚点逻辑。

鼠标滚轮改用离散 `zoomStep`，触控板双指滑动继续使用 `panBy`。因此鼠标滚轮和触控板滑动不会误判为同一种手势。

## 使用前检查

1. 将指针放在星图空白区域，详情卡片、设置面板和 Dock 上的手势由对应控件处理。
2. 在“设置 → 视角与导航”确认“鼠标或触控板移动星图”和“鼠标滚轮或触控板缩放”已开启。
3. 如果双指捏合仍无响应，先确认系统触控板设置没有把双指捏合映射为系统缩放，再重新把指针移入星图区域。
4. 该路径不读取设备序列号、UDID、位置或网络数据。

## 验证边界

CLI 可以验证设置开关、FOV、`zoomBy`/`zoomStep`/`panBy` 命令和构建结果，但不能伪造 MateBook 的物理触控板轴事件。真机最终验收需要在 PC/2in1 上实际双指滑动与捏合一次。
