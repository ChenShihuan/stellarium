2. 三层运行时架构

应用是「ArkTS 外壳 + C++ 命令桥 + Qt 引擎」的三段结构。ArkUI 负责一切界面与交互；真正的星图由 Qt/Stellarium 渲染成帧，通过 XComponent 交给 ArkUI 显示。

① ArkTS / ArkUI 层 libentry.so 的调用方
pages/ApplicationRoot.ets（唯一 @Entry，隐私/启动/主界面三选一）→ pages/MainWindowNativeNode.ets（壳层、Dock、面板、星图触摸、帧显示）
契约类型集中在 pages/StellariumTypes.ets；国际化 pages/I18n.ets； 中文位置库 pages/location_*.ts
▲ ▼   command(name, payload) → JSON string（NAPI，同步）
② NAPI 命令桥 libentry.so ← cpp-source/hello.cpp
导出 add / setEnv / command；用 dlopen(RTLD_NOLOAD) 查找 libstellarium.so 的 StellariumOhos_command； 另负责 XComponent 回调注册与 submitFrame/submitTexture 帧提交
▲ ▼   StellariumOhos_command(name, payload) → JSON（Qt 主线程）
③ Qt / Stellarium 引擎 libstellarium.so（41 MB，即 Qt 应用二进制）
src/StelMainView.cpp（渲染/计算/选星/搜索）+ src/StelOhosCommandCatalog.hpp（命令目录）+ 插件（Satellites / MeteorShowers / Novae / NebulaTextures…）
运行库：15 个 libQt6*.so + libqohos.so（平台插件）+ libmd4c/md4c-html/nlopt
▼   OpenGL ES → XComponent(SURFACE) → PBO 异步回读 → ArkUI 显示

两条 XComponent 通道

通道声明作用
SURFACE 探针 XComponent({type: XComponentType.SURFACE, id:'stellarium_entry_gl_probe', libraryname:'entry'})
zIndex 0 · HitTestMode.None		 承载 EGL 上下文与帧回读（PBO 异步），把 Qt 渲染结果交给 ArkUI 合成
NODE 原生节点 XComponent({type: XComponentType.NODE, id:createInfo.xComponentId, libraryname:'qohos'})
zIndex -1 · opacity 0.01 · HitTestMode.None · enabled(false)		 Qt 自己的窗口节点（Qt for OHOS 平台插件 qohos 接管），受隐私门控后才创建

4. 启动时序（从 Ability 到首帧）

#阶段关键调用 / 日志
1AbilityStage 启动QAbilityStage::onCreate()；因隐私未决而延后 Qt 创建（[privacy-gate] deferred AbilityStage create）
2窗口与页面preparePrivacyHostPage() → getMainWindow() → new QtWindowStageAdapter(...) → loadContent('pages/ApplicationRoot', rootStorage)（全程只加载一次）
3沉浸式与安全区enterImmersive(windowStage)；publishScreenSafeArea(avoidArea.topRect.height) → AppStorage stellariumScreenSafeTopPixels
4系统隐私请求官方隐私弹窗；同意后置 stellariumPrivacyNativeStartupAllowed = true（[privacy-gate] system privacy consent accepted）
5资源 bootstrap StellariumResourceBootstrap.prepareStellariumResourcesAsync()：把 rawfile/stellarium/ 整棵树复制到沙箱，写 STELLARIUM_DATA_ROOT 等环境变量；校验 10 个启动必需路径与标记文件
6Qt 上下文[privacy-probe] phase=qt-context-init-start → 平台插件加载 /data/storage/el1/bundle/libs/arm64/libstellarium.so → QAbilityStage 转交成功
7首帧StelRootItem paint reached、zero-copy frame bridge resolved、startOhosRenderPump entered、framebuffer viewport …
8命令桥上线ArkTS 侧轮询 command('getAppState') 直到 bridge resolved，随后 setLanguage 等命令在 Qt 线程执行（ohosDrainCommandQueue）
9启动层淡出stellariumStartupSkyReady + …ArtComplete → animateTo(STARTUP_REVEAL_MS) → loadingVisible=false（[startup] sky-revealed）
关键设计：Qt 主线程由 Qt for OHOS 平台插件创建并驱动渲染泵，不走 Qt 事件循环；因此跨线程投递的命令由 C++ 侧在每帧排空（ohosDrainCommandQueue），而不是依赖 QueuedConnection。

5. 命令桥契约（libentry.so）

5.1 对外导出（cpp-source/types/libentry/index.d.ts）

export const add:     (a: number, b: number) => number;
export const setEnv:  (name: string, value: string) => boolean;
export const command: (name: string, payload: string) => string;   // 返回 JSON 字符串

模块注册（hello.cpp 尾部）：napi_define_properties 暴露三个函数 + registerNativeXComponent；napi_module.nm_modname = "entry"，由 __attribute__((constructor)) RegisterEntryModule() 注册。

5.2 加载策略（最容易踩的坑）

void* handle = dlopen("libstellarium.so", RTLD_NOW | RTLD_NOLOAD);   // 只查“已加载”的库
if (!handle) return nullptr;   // 未就绪时返回 null，由 ArkTS 侧重试
command = dlsym(handle, "StellariumOhos_command");
为什么必须 RTLD_NOLOAD：若在 ArkUI 线程主动 dlopen 首次加载，会与 Qt 平台插件的 makeQtThreadWithMainFuncLauncher 抢占主线程上下文，触发 Qt API was likely used before Qt initialization. Aborting. → 进程 SIGABRT。

5.3 调用语义

行为说明
未就绪返回 {"ok":false,"error":"bridge not available"}；ArkTS 侧重试直到成功
本地短路命令getPresentationState 由桥直接应答（不进入 Qt），用于判断首帧是否就绪
静默命令dragView / zoomBy / panBy / setGyroView 不写日志，避免拖动手势期间与 UI 线程争用
回包格式统一 JSON：{"ok":true,…} / {"ok":false,"error":"…"}；ArkTS 侧对应 StellariumBridgeResponse

6. 界面与窗口层级（摘要）

完整版见 docs/harmonyos/specs/UI-ARCHITECTURE.md（含代码行号与核对命令）。要点：

窗口层：单 Ability / 单窗口 / 单次 loadContent('pages/ApplicationRoot')；QtWindowStageAdapter 不二次加载
▼
页面层：ApplicationRoot = 主界面 / 启动汇字覆盖层 / PrivacyBootstrap 三选一
▼
叠放层：MainWindowNativeNode.build() 根 Stack —— zIndex -1 语言锚点与 Qt NODE、0 EGL 探针与触摸反馈、壳层与四类 Overlay、92 状态条、98/99 夜间模式膜
▼
壳层：harmonyShell → compactShell / expandedShell / hoverObservatoryShell，由窗口短边与折叠角判定（短边 < 520 → compact；≥ 700 或 900×520 → expanded）
触摸层铁律：星图触摸只挂专属触摸面（Block），UI 组件各自 onClick；禁止用全屏 Column + HitTestMode.Block 覆盖——历史上这样改导致星图不可拖、星星点不中、Dock 失灵，整个 commit 被回退。

10. 关键约束与常见坑

约束 / 坑后果与做法
必须构建 build/libstellarium-harmonyos/在 harmonyos/ 里跑 hvigor 会报 Path not found …/harmonyos/entry（镜像没有 entry 模块）
modelVersion 必须两处一致oh-package.json5 与 hvigor/hvigor-config.json5 同为 26.0.0，否则 IDE 直接报错
签名只能由 DevEco 自动签名产生自签（OpenHarmony CA）会被真机拒绝：code:9568257 fail to verify pkcs7 file
ArkUI 线程不得抢先 dlopen 引擎触发 Qt API was likely used before Qt initialization. Aborting.；只允许 RTLD_NOLOAD 查找
星图触摸不能挂全屏 UI 父会吞掉子组件 onClick；用专属触摸面
HAP 内 Qt 依赖名不能是构建树路径CPM 依赖无 SONAME 时 DT_NEEDED 会写成 _deps/…，装机后 dlopen 失败；需等长改写并补齐 libmd4c/md4c-html/nlopt
资源树缺失 = Qt 拒绝启动Startup resources are incomplete after asynchronous extraction
DevEco 开着时构建加 --no-daemon否则其常驻 daemon 接管任务并报 spawn java ENOENT
模拟器是 x86_64，应用是 arm64Windows 模拟器跑不了星图（Qt 无 x86_64 目标）；只能验证 ArkUI 外壳（abiFilters 加 x86_64）
真机启动需解锁并保持亮屏开发者模式下系统不允许自动解锁：aa start 返回 10106102
